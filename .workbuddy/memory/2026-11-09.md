**踩坑（重要）**
1. `av_seek_frame(format, streamIndex, ts, ...)` 的 `ts` 必须用该流的 time_base；传 `AV_TIME_BASE` 会静默落到错误位置。缩略图抽帧统一用 `stream_index = -1`，时间单位 `AV_TIME_BASE`。
2. 片头常为黑场：缩略图不能取第 0 帧，要 seek 到片长的 ~10%（本实现最少 1s、最多片尾前 1s）。

5. headless 模拟器不允许 `requestGeometryUpdate`（多窗口模式报 “current windowing mode does not allow…”），无法脚本旋转 iPad；横屏验收留到 8.7。iPad Air 13 竖屏 1024pt 已实证 4 列。

## 2.5 / 2.7 读调度与预读环（完成，38/66）

**实现**
- `SMBSession.SMBReadPriority`：playback 0 / enumeration 1 / thumbnail 2。
- `SMBSession.SMBReadScheduler`：单线程 + NSCondition 优先队列，所有 SMB 读取串行；支持 30s 超时、`cancelAll(error:)` 在断连时终结挂起请求；debug 日志记录优先级、等待、执行耗时。
- `SMBSession.SMBChunkRing`：1MB 分块、24 块（24MB）LRU 环；支持跨块切片、EOF 短块、缺口判定。
- `SMBFileByteSource`：1MB 块读取 + 24MB 环；顺序读后台预读（enumeration 优先级，避免抢播放）；跳转清环；句柄失效重开；抽帧源用 256KB 块 + 8 块环，缩短单次占用读线程的时间。
- `SMBClient` 共享一个 `readScheduler`；`disconnect` 时 `cancelAll`；`openByteSource(path:priority:)`；`ThumbnailByteSourceProvider.openThumbnailByteSource` 走 thumbnail 优先级。
- 自检参数 `-libraryAutoPlayFirst`：目录加载后自动播放第一个视频，用于制造播放 + 抽帧并发。

**真机实测（SMB，30s，24 个缩略图冷缓存）**
- thumbnail：656 次读、162.3MB，等待 p50 20ms / max 245ms，执行均值 12.3ms。
- playback：6 次读（其余由 24MB 预读环命中）、5.5MB，等待 p50 9.5ms / p95 12ms / **max 26ms**，执行均值 36.5ms。
- prefetch：24 次 enumeration 读、24.0MB，等待 max 32ms。
- 结论：抽帧并发下播放读等待 p95 12ms，满足「不显著上升」。播放画面与字幕正常，25 秒位置继续推进。

**测试**：72 个单元测试全通过（新增 3 个调度器 + 5 个环测试）；`openspec validate --strict` 通过。
