# Design

## Context

`LibraryPoster` 对目录条目固定渲染 `folder.fill`，从不请求缩略图。视频抽帧已有 `DemuxProbe.thumbnail(source:label:maxWidth:position:)`，默认取片长约 10% 的位置；`ThumbnailService` 以 3 并发服务所有文件封面。目录条目没有大小与修改时间语义，不能直接复用共享侧车的文件索引。参见 proposal.md - Why。

## Goals / Non-Goals

**Goals**

- 目录有内部视频时显示中间帧封面，优先直接子视频，最多向下两层。
- 抽帧失败自动换候选，全部失败回退文件夹图标。
- 目录封面与视频封面缓存隔离、并发隔离，不拖慢滚动。
- 缓存键包含内部视频身份，视频变化后封面失效。

**Non-Goals**

- 不递归扫描任意深度，不遍历整个共享。
- 不把目录封面写入 `.icemovie` 共享侧车索引。
- 不为无视频目录生成生成式封面。
- 不改变视频条目自身的抽帧位置（仍为 10% 的代表帧）。

## Decisions

### D1. 抽帧位置用比例而不是绝对秒数

`DemuxProbe` 在打开媒体后才知道时长。给 `thumbnail(source:...)` 增加 `positionFraction: Double?`，在 `decodeFirstFrame` 里按 `duration * fraction` 计算目标时间；目录封面传 `0.5`。相比在调用方先探测时长，只多一次内部计算，不增加 SMB 读取。

### D2. 目录候选解析

候选顺序：直接子视频（按 `MediaOrdering` 自然排序）→ 若没有，按名称扫描最多 4 个直接子目录，各取第一个视频。每个目录最多保留 3 个候选，逐个尝试抽帧。列表结果按目录路径缓存到当前会话，避免每次滚动重复枚举 SMB 目录。

### D3. 独立单并发封面队列

新增一个 `ThumbnailService` 实例专用于目录封面，`maxConcurrent = 1`，与文件封面的 3 并发隔离。单元格出现后延迟 150ms 再启动，滑出即随 `.task` 取消；这样目录封面不会挤占可见视频封面的读取槽。

### D4. 独立 16MB 本地缓存 + 持久化候选，不写共享侧车

目录封面是派生数据，且一个目录可能对应多个候选视频。缓存键使用 `folder-cover-v1|<目录路径>|<候选视频路径>|<大小>|<修改时间>`，写入独立的 `Caches/FolderCovers`（16MB LRU），不与文件缩略图共用 64MB 缓存。视频预热会持续写入并触发 LRU 淘汰，共用缓存时目录封面容易被当成旧条目清掉；独立缓存保证第二次进入仍能命中。

只缓存图片还不够：启动后若先枚举目录寻找候选，网络慢时仍会像“每次现生成”。因此把上次选中的内部视频（路径、大小、修改时间、解析时间）持久化到 `Caches/FolderCoverSelections.json`，缓存命中时直接计算缓存键读本地封面，**不发起任何 SMB 目录枚举**。选择 24 小时过期；过期或本地封面被淘汰时才重新解析候选。候选按路径稳定排序，避免跨启动选中不同视频导致缓存键漂移。不扩展共享索引，避免目录键污染文件条目清理逻辑。

### D5. UI 呈现与布局稳定

目录卡片仍保持 2:3 比例。有封面时图片 `scaledToFill` 并裁切，左下角叠加半透明文件夹角标；没有封面时沿用渐变 + `folder.fill`。封面加载不改变卡片高度，不引入新的滚动布局计算。

### D6. 取消与失败处理

`LibraryPoster` 的 `.task(id:)` 在条目变化或滑出时取消；`LibraryStore` 为每个目录维护 in-flight 任务，取消后移除。候选抽帧失败只记录日志并尝试下一个；全部失败时返回 `nil`，本次会话对该目录不再重复扫描，直到目录重新加载或应用重启。

## Risks / Trade-offs

- [多一次 SMB 目录枚举] → 只对可见目录执行，结果按会话缓存；每个目录最多 5 次枚举（自身 + 4 个子目录）。
- [首个候选视频损坏] → 最多尝试 3 个候选，失败后回退图标并记录日志。
- [目录封面挤占带宽] → 独立单并发队列 + 150ms 延迟 + 滑出取消。
- [目录封面被文件缩略图淘汰] → 使用独立 16MB `Caches/FolderCovers`，启动时单独裁剪，清空缓存时一并删除。
- [内部视频变化后会话内不刷新] → 缓存键包含视频身份；重新进入目录或重启应用会重新解析候选，必要时可后续增加定时刷新。
- [中间帧接近纯色/黑场] → 中间帧通常比片头更有代表性；仍无法解码时走候选回退。

## Migration Plan

无数据迁移。新增缓存键使用独立命名空间，不影响现有文件封面；清理缓存时随 `ThumbnailStore` 一起淘汰。
