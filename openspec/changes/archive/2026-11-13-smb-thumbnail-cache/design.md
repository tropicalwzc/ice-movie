# Design

## Context

当前网格缩略图由客户端从 SMB 原图生成，缓存只在本地。3,596 张照片的目录里，单张封面平均读取约 2.8MB，首次滚动受 SMB 带宽和逐文件延迟限制。`ThumbnailService` 已有本地磁盘缓存、384px 生成、EXIF 前缀、后台解码、取消与空闲预取；`LibrarySource`/`SMBClient` 已支持 SMB 读写与原子覆盖。

本设计只覆盖当前用户实际使用的那一个照片目录，不递归扫描其他目录。

## Goals / Non-Goals

**Goals:**

- 在共享内建立可复用的缩略图与宽高索引，后续滚动只读几十 KB。
- 首次进入目录自动全量预热，可见项优先，可暂停/继续/取消，可断点恢复。
- 新照片、变化照片增量预热；删除文件同步清理。
- 共享只读或缓存损坏时无感降级到现有本地缓存 + 原图流程。

**Non-Goals:**

- 不修改原图，不做服务端图像处理。
- 不递归预热整个共享，只处理当前目录。
- 不引入远端数据库；索引是共享上的普通 JSON 文件。
- 不替代本地 64MB 缩略图缓存，二者是 L1/L2 关系。

## Decisions

### D1. 共享侧车目录结构

共享根下新增：

```text
.icemovie/
  version
  index.json
  thumbs/
    ab/
      <thumbHash>.jpg
```

- `index.json` 只描述当前预热目录（当前用户只有一个照片目录）；条目键为相对路径。
- 缩略图按 hash 前两位分片，避免单目录数千文件。
- `version` 记录缓存结构版本；版本不匹配时整体忽略并重建，不尝试迁移旧缓存。

替代方案：每个目录一个 index。当前只有一个目录，增加复杂度没有收益，不采用。

### D2. 缓存键与索引

- `thumbHash = SHA256(相对路径 + "|" + 文件大小 + "|" + 修改时间)`，取前 32 个十六进制字符。
- 条目字段：`thumb`、`width`、`height`、`size`、`modified`。
- 宽高来自最终缩略图（已应用方向），直接用于瀑布流布局。
- 源文件大小或修改时间变化 → 新 hash，旧缩略图自然失效。

替代方案：用路径直接做文件名。路径含中文、空格和特殊字符，跨 SMB 客户端兼容性差；不采用。

### D3. 读取优先级

```text
NSCache
  -> 本地 64MB 缩略图
    -> SMB .icemovie/thumbs
      -> 原图 EXIF/整图生成
```

- 在 `ThumbnailService` 增加可选的 `ThumbnailSidecarProviding`；SMB 源实现，其他源返回 nil。
- 侧车命中后仍写入本地缓存与内存缓存，后续翻回该页不再走 SMB。
- 侧车缩略图解码失败视为 miss，删除该文件并回退原图。

### D4. 原子写入与索引批量更新

- 缩略图：写 `*.tmp-<uuid>` → 校验大小 → rename 为 `<hash>.jpg`。
- 索引：内存合并条目，每 20 张或每 5 秒写一次；暂停、完成、退出时强制 flush。
- 索引写失败只丢布局元数据，缩略图文件仍可在下次通过 hash 识别并重新补索引，不重新生成图片。

### D5. 预热调度

三级优先级：

```text
P0 当前可见单元格
P1 滚动方向前方
P2 全量预热
```

- 进入照片目录且侧车有缺失时自动开始。
- P2 只占一个并发槽；可见单元格仍走现有 3 并发。
- `LibraryGridView` 通过 `onScrollPhaseChange` 通知 `LibraryStore` 滚动状态；P2 在滚动期间暂停，停止 2–3 秒后继续。
- 预热状态包含 `total/completed/running/paused/current`，由 `LibraryStore` 暴露给顶部进度条。
- 暂停/继续/取消是显式操作；退出目录停止，下次进入从缺失项继续。

替代方案：预热和可见请求共用 3 个槽。会拖慢首屏，不采用。

### D6. 可见项优先，不额外做全量元数据扫描

全量元数据扫描需要为 3,596 张图额外打开一次文件，SMB 每文件延迟会显著拉长首轮。因此：

- 预热队列把当前可见条目排在最前，缩略图生成成功时顺带写宽高。
- 不做独立的 64KB 全目录尺寸扫描；已有本地 `ThumbnailAspects` 继续作为补充来源。
- 首屏可能在缩略图到达时调整一次高度，滑动期间已暂停改高度；完成首轮后所有条目布局稳定。

### D7. 断点恢复与增量

- 预热队列只保存内存状态；恢复时重新列目录、读索引，按条目检查缩略图是否存在。
- 索引落后时，通过计算 hash 直接探测 `thumbs/<prefix>/<hash>.jpg`；存在则补索引，不重新生成。
- 目录重新加载时对比索引与实际文件：
  - 缺失条目 → 入队；
  - 多余条目 → 删除索引与缩略图；
  - 大小/时间变化 → 新 hash 入队，旧文件清理。

### D8. 只读与失败降级

- `ThumbnailSidecarProviding` 写入第一次失败后，本次会话标记为不可写，后续只读不写。
- 创建 `.icemovie` 或无写权限时，静默回退现有本地缓存 + 原图流程。
- 索引损坏：删除/忽略索引，预热重新建立。
- 缩略图损坏：删除并回退原图生成。

### D9. 后台继续

- 前台预热时禁用自动锁屏，显示进度与暂停按钮。
- 充电且空闲时通过 `BGProcessingTask` 继续；任务被系统挂起后，下次启动按缺失项恢复。
- `BGProcessingTask` 只处理当前目录，不递归。

### D10. 滚动帧率

- 不使用 `.scrollPosition(id:)` 持续跟踪当前条目。它会在滚动目标变化时触发整个网格 body 重算，3,800+ 条目下实测只有 33–45fps。
- 改为 `ScrollViewReader`：只在进入目录时恢复一次锚点、在日历/搜索跳转时调用一次 `scrollTo`；可见锚点通过 `.onScrollTargetVisibilityChange` 写入非 Observable 的 tracker，不触发 SwiftUI 刷新。
- 移除“每个 cell onAppear 都重排预热队列”的 O(n) 操作；预热顺序已按目录顺序进行，滚动期间 P2 本身会暂停。
- 新增 `-fpsMonitor` + `CADisplayLink` 诊断，60Hz iPad 10 次滑动验收线为 ≥50fps；优化后实测 54.5–57.2fps。
- 10-bit/广色域 HEIC 解码后若 PNG/JPEG 编码失败，先归一化为 8-bit sRGB 再编码，避免预热因 6 张老 HEIC 反复重试。

## Risks / Trade-offs

- **首轮 10–25 分钟** → 进度可见、可暂停、可断点恢复；首屏宽高优先；后续增量。
- **预热抢 SMB 带宽** → P2 单并发，滚动暂停；可见请求优先。
- **共享写入失败/只读** → 静默降级本地缓存，不影响浏览。
- **多设备同时预热** → 临时文件 + 原子 rename，不会写坏；可能重复生成，接受。
- **索引并发覆盖** → 索引是缓存，最多丢少量条目，下次按 hash 补齐。
- **`.icemovie` 占用共享空间** → 384px JPEG 单档，3,596 张约 100–200MB；提供孤儿清理，后续可加配额。
- **文件被覆盖但大小和时间不变** → 与现有缓存键一致，极端情况下命中旧图；概率低，接受。

## Migration Plan

- 首次升级：共享无 `.icemovie` 时创建并写入 `version=1`。
- 版本不匹配：忽略旧索引与缩略图，后台重建；不删除原图。
- 本地缓存与 `ThumbnailAspects.json` 保持兼容，不需要清理。
- 回滚：删除 `.icemovie` 即可；App 自动退回原图流程。

## Open Questions

- 共享根是否允许创建隐藏目录：用户已确认允许。
- 缓存配额：首版不设硬上限，只做孤儿清理；后续按实际占用再加。
