# Proposal

## Why

当前媒体库把 SMB 共享当作原图 CDN，网格滚动时才由客户端读取原图并生成缩略图。3,596 张照片的目录中，单张封面平均读取约 2.8MB（最大 9.9MB），首次滚动受 SMB 带宽和逐文件延迟限制，预热前始终存在空白与等待。

共享主机有充足磁盘，允许在共享内保存缩略图。把缩略图变成共享侧的可复用缓存后，首次全量预热只需一轮，之后所有设备、所有会话都只读几十 KB 的小文件；新照片再增量补齐。

## What Changes

- 在共享根目录新增隐藏缓存 `.icemovie/`：`index.json` 记录宽高、缩略图键与源文件大小/修改时间，`thumbs/` 存放 384px JPEG 缩略图。
- 缩略图读取顺序改为：内存 → 本地磁盘 → SMB 侧车缓存 → 原图；侧车命中时不再读取原图。
- 侧车 miss 时仍走现有原图/EXIF 前缀生成流程，生成成功后后台原子写回共享，并批量更新索引。
- 进入照片目录时自动启动全量预热：可见项优先，滚动时暂停，顶部显示进度，可暂停/继续/取消；退出后停止，下次进入从缺失项继续。
- 首轮完成后进入增量模式：列目录时对比索引，只处理新增、大小或修改时间变化的文件；删除文件同步清理索引与孤儿缩略图。
- 共享只读、写入失败或缓存损坏时自动退回现有本地缓存 + 原图流程，不阻塞浏览。
- 缓存键为「相对路径 + 文件大小 + 修改时间」，文件名使用内容哈希并按前两位分目录，避免单目录文件过多。

## Capabilities

### New Capabilities

- `thumbnail-cache`: 定义共享侧缩略图缓存的目录结构、索引、读取优先级、原子写入、失效清理、全量预热、增量预热与只读降级。

### Modified Capabilities

- `media-library`: 网格缩略图可来自共享侧车缓存；再次进入目录时优先使用本地或共享缓存，不再要求必须从本地缓存读取。

## Impact

- 新增 `ThumbnailKit` 共享侧车缓存协议与 SMB 实现。
- 修改 `ThumbnailService` 读取链路、`LibraryStore` 缩略图入口与预热调度。
- 修改 `LibrarySource`，增加共享缓存目录的读、写、列目录与删除能力。
- 新增 `.icemovie/` 目录写入与原子替换；仅缓存缩略图，不改原图。
- 需要处理 SMB 写入失败、只读共享、断线重连、缓存版本升级与孤儿清理。
