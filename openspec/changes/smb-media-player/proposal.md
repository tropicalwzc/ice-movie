# Proposal

## Why

家里一台 Windows 主机通过 SMB 共享了 `Animi` 目录（测试环境地址 `192.168.5.2`，仅供验证；日常使用以局域网主机名或别名访问，地址由 DHCP 分配，不可假定固定），实测有 **754 个视频文件**，其中 **MKV 514 个（68%）**，抽样显示几乎全是 1080p 10-bit HEVC，音轨混杂 AAC / Opus / AC3 / FLAC。iOS 上不存在能覆盖这套素材的系统方案：AVFoundation **不支持 Matroska 容器**，514 个 MKV 用系统播放器的成功率为零；而这些片子绝大多数带字幕组精校的 ASS 字幕（抽样 9 个含内封字幕的 MKV 中 8 个是 ASS，另有 188 个与视频同名的外挂 `.ass`），第三方播放器要么不支持 SMB 直连，要么拖动进度条要等待转码。

目标是一个自用播放器：**打开就连上、点开就播、拖动就出画、字幕保留原样式**。

## What Changes

- 新建一个 iOS 26+ 的 SwiftUI 应用工程，最低部署版本 iOS 26.0，**同时支持 iPhone 与 iPad**；iPad 是主要使用场景，至少保证 11 英寸 iPad Air 上完整可用。
- 接入 SMB2/3 客户端（AMSMB2，封装 libsmb2），支持账号密码认证、共享列表枚举、目录遍历；凭据存入 Keychain，主机与最近访问路径持久化，App 重启后自动恢复连接，无需重复输入。
- 主机以用户输入的地址为准，**不绑定任何固定 IP**：地址可以是 IPv4/IPv6、DNS 主机名、`.local` 形式的局域网名称或 Windows 主机名；连接记录保存用户输入的原始地址，每次连接重新解析，DHCP 换址后仍可连通。
- 建立连接健康机制：空闲心跳、断线检测、指数退避重连，单次读写超时可控，避免长连接静默失效导致播放中断。
- 自建播放内核，统一处理 MP4 与 MKV，**不区分两套播放器**：
  - FFmpeg（libavformat/libavcodec/libswscale/libswresample）负责解封装、音频解码、字幕包提取、封面抽帧；
  - 视频帧以压缩 `CMSampleBuffer` 直接入 `AVSampleBufferDisplayLayer`，由系统内部走 VideoToolbox 硬解，不做软件解码、不做转码；
  - 音频解码为 PCM 后交给 `AVAudioEngine` 渲染，音频硬件时钟作为主时钟驱动画面与字幕。
- 播放控制对齐系统播放器：进度条拖动即时响应、松手精确定位、播放/暂停、快进快退、音量与亮度手势、全屏切换、后台音频、画中画；在 iPad 上额外支持外接键盘快捷键、指针悬浮反馈，并可在分栏状态下以内联或全屏两种方式观看。
- 字幕渲染采用 libass：支持 MKV 内封 ASS/SSA/SRT 与外挂 `.ass`/`.srt`，保留字体、定位、特效等原始样式，支持多语言轨道（如 `chs` / `cht` / `jpn` 三语并存）切换与字号调整。
- 媒体库以网格呈现，并按可用宽度自适应：iPhone 紧凑宽度为单栈导航，iPad 常规宽度用分栏结构，左侧承载主机、共享与目录层级，右侧承载网格；窗口在分栏、滑动覆盖、台前调度或自由窗口下任意改变宽度时布局不得错乱。
- 缩略图管线：可见区域优先抽帧、磁盘缓存、并发受限、优先读取 MKV 内嵌封面，不做全量预生成。

## Capabilities

### New Capabilities

- `smb-connection`: SMB2/3 会话的建立、认证、凭据安全持久化、自动重连与连接健康检测，以及共享与目录的读取接口。
- `media-library`: 媒体库的目录导航、网格呈现、标题解析与排序、缩略图生成与缓存、检索能力。
- `video-playback`: 统一播放内核的解封装、硬解渲染、音频输出、主时钟同步、进度控制与任意位置跳转。
- `subtitle-rendering`: 字幕轨道的发现与匹配、ASS 样式化渲染、轨道切换与样式调整。

### Modified Capabilities

无。本项目为全新工程，`openspec/specs/` 下尚无既有能力。

## Impact

- **代码**：全新 Xcode 工程，无既有代码需要迁移。
- **第三方依赖**：
  - `AMSMB2`（Swift 包，静态链接 libsmb2，LGPL-2.1；应用分发时需注意动态链接要求，自用侧载不受影响）。
  - FFmpeg 静态库 + `libass` / `freetype` / `fribidi` / `harfbuzz`。上游 FFmpegKit 已退役，需通过 FFmpegKitNext 的构建脚本或社区重编译产物产出 xcframework，**该环节存在构建风险，需先行验证**。
  - 需随包携带一份中文字体（或从 MKV 字体附件中提取），否则 ASS 中文样式会回退为方框。
- **系统权限与配置**：`NSLocalNetworkUsageDescription`（iOS 14+ 首次访问局域网会弹授权框）、`UIBackgroundModes: audio`、`AVAudioSession` 播放类别。
- **已知能力边界**：`AVSampleBufferDisplayLayer` 不支持 AirPlay 视频投放，本变更不承诺该能力；PiP 支持。
- **验证分层**：解封装、解码、音画同步、跳转逻辑、字幕渲染与网格布局属于纯本地逻辑，用截取自真实库的短样本在模拟器中验证，可反复回归；SMB 连接、认证、重连、地址解析，以及首帧时延、拖动时延、吞吐与功耗必须由人工在真机上对着真实共享验收。
- **验证条件**：真机验收需要一台 iPhone 与一台 11 英寸 iPad Air 各跑一遍；验收素材为测试主机上的 `Animi` 共享（当前环境为 `192.168.5.2`，仅作为测试夹具，不写入任何默认值或常量）。
- **法律与合规**：素材为个人收藏，应用不涉及内容分发。
